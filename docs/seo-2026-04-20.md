## 1. 작업 배경과 전제

### 왜 이 작업이 필요했나
1. **리치 결과 미노출 위험**: JSON-LD Article 없이는 Google이 "블로그 글"로 인식하더라도 작성자/발행일/카테고리 같은 구조화 정보를 제공할 수 없어 검색 결과가 단순 파란 링크에 머무름
2. **소셜 공유 썸네일 누락**: 슬랙·디스코드·카카오톡에 URL 붙여넣을 때 OpenGraph 메타가 없어 제목만 표시됨 → 클릭 유도력 낮음
3. **중복 URL 색인 위험**: canonical 태그 미설정 → `/?cursor=…`, 대소문자 변형 URL 등이 별도 페이지로 색인될 수 있음
4. **사이트맵 품질 저하**: 카테고리의 `lastModified`가 매번 `new Date()` → 크롤러가 "매번 바뀐다"고 판단 → 신뢰도 하락 가능
5. **검색 결과 페이지 색인**: `/search?q=...` 같은 쿼리 조합이 색인 대상이 되면 중복 콘텐츠 페널티 유발
6. **Naver 유입 경로 부재**: 한국어 블로그의 Naver Search Advisor 인증 태그 스캐폴딩이 없어 유사 태그 작업 반복 필요

### 개선 전 진단
| 영역 | 이전 상태 | 문제 |
|------|-----------|------|
| 전역 메타 | title + description만 | `metadataBase`, OG, Twitter 모두 없음 |
| 포스트 메타 | title + description만 | publishedTime/tags/images/canonical 전무 |
| JSON-LD | 없음 | 리치 결과 기회 상실 |
| OG 이미지 | 글 상세만 (opengraph-image.tsx) | 홈/카테고리/태그는 이미지 없음 |
| Canonical | 없음 | 중복 URL 색인 위험 |
| 사이트맵 | 기본 post + category | lastMod가 항상 now, priority/changeFreq 없음 |
| RSS | 없음 | 피드 리더/애그리게이터 유입 경로 없음 |
| 검색 페이지 | index 허용 | 쿼리 페이지 색인 리스크 |
| Naver | 없음 | 한국 검색 엔진 미등록 |

## 2. 작업 내역

### 2.1 사이트 상수 모듈 (`lib/site.ts`)

**왜 만들었나**
- 사이트 이름·URL·저자·locale이 여러 파일에 하드코딩되면 문구 변경 시 누락 발생
- OG, JSON-LD, RSS가 동일 정보를 참조해야 일관성 유지

**결과물**
```ts
export const site = {
  name: 'ShyLog',
  title: 'ShyLog — 개인 기술 블로그',
  description: 'Shylog: 개발 블로그',
  url: process.env.NEXT_PUBLIC_SITE_URL ?? 'https://www.shylog.com',
  locale: 'ko_KR',
  author: {
    name: 'Soshy',
    url: 'https://github.com/NJ97S',
  },
}
```

**효과**
- 이후 모든 SEO 관련 문자열이 단일 소스 참조 → DRY
- locale `ko_KR` 통일 → OG 파서가 한국어 콘텐츠로 정확히 분류
- author.url이 GitHub를 가리킴 → JSON-LD `sameAs`로 활용 시 Google Knowledge Graph의 entity 매칭에 도움

### 2.2 JSON-LD 헬퍼 (`components/JsonLd.tsx`)

**왜 만들었나**
- Article, BreadcrumbList, WebSite 등 여러 schema를 여러 페이지에서 삽입해야 함
- 매번 `<script type="application/ld+json" dangerouslySetInnerHTML>`을 인라인으로 쓰면 실수 유발

**결과물**
```tsx
export default function JsonLd({ data }: { data: Record<string, unknown> }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(data) }}
    />
  )
}
```

**효과**
- 호출부가 한 줄로 단순화 (`<JsonLd data={articleSchema} />`)
- server/client component 모두에서 동작 (stateless render)
- JSON 이스케이프는 `JSON.stringify`가 자동 처리 → XSS 위험 없음

---

### 2.3 사이트 전역 OG 이미지 (`app/opengraph-image.tsx`)

**왜 만들었나**
- 글 상세 페이지는 기존 OG 이미지 있음 (`app/posts/[slug]/opengraph-image.tsx`)
- **홈/카테고리/태그/검색**은 OG 이미지 없음 → 공유 시 이미지 없는 회색 카드만 노출
- Next.js App Router는 루트에 `opengraph-image.tsx`를 두면 자식 라우트가 자동 상속

**결과물**
- `app/opengraph-image.tsx`: `ImageResponse`로 "ShyLog" 타이틀 + "Shylog: 개발 블로그" 서브타이틀을 표시하는 1200×630 PNG 동적 생성
- 배경 `#fdf8f0` (craft-50), 텍스트 `#1a1410` (ink-900) — 사이트 컬러 팔레트 준수

**효과**
- 공유 시 브랜드 아이덴티티 유지
- Article 개별 이미지가 없는 글도 fallback으로 이 이미지 사용 가능
- Edge runtime (`export const runtime = 'edge'`) → 전역 엣지에서 빠르게 서빙

### 2.4 전역 메타데이터 (`app/layout.tsx`)

**왜 확장했나**
- `metadataBase`가 없으면 Next.js가 OG 이미지·canonical에 상대 경로 사용 → 크롤러가 원본 URL 추정 못함
- OG/Twitter가 없으면 공유 카드 빈약
- 검색 엔진 스니펫 제어를 위해 `googleBot` 세부 옵션 필요

**변경 요점**
```ts
export const metadata: Metadata = {
  metadataBase: new URL(site.url),
  title: { default: site.title, template: `%s · ${site.name}` },
  description: site.description,
  authors: [{ name: site.author.name, url: site.author.url }],
  creator: site.author.name,
  publisher: site.author.name,
  alternates: {
    canonical: '/',
    types: { 'application/rss+xml': [{ url: '/rss.xml', title: `${site.name} RSS` }] },
  },
  openGraph: { type: 'website', siteName, locale: 'ko_KR', url: '/', title, description },
  twitter: { card: 'summary_large_image', title, description },
  robots: {
    index: true,
    follow: true,
    googleBot: { index: true, follow: true, 'max-snippet': -1, 'max-image-preview': 'large', 'max-video-preview': -1 },
  },
  verification: naverVerification ? { other: { 'naver-site-verification': naverVerification } } : undefined,
}
```

**세부 효과**
- `metadataBase`: 모든 상대 경로 metadata가 절대 URL로 변환 → OG 이미지·canonical·sitemap 모두 정확
- `googleBot.max-image-preview: 'large'`: Google Discover·검색 결과에서 큰 썸네일 허용
- `googleBot.max-snippet: -1`: 스니펫 길이 제한 없음 → 전체 설명 표시 가능
- `alternates.types`: RSS 피드 자동 발견 링크를 `<head>`에 삽입 → Feedly/브라우저가 피드 존재 감지
- `verification.other['naver-site-verification']`: env 기반으로 스캐폴딩 → 코드만 발급받으면 즉시 반영

### 2.5 포스트 상세 메타 확장 (`app/posts/[slug]/page.tsx`)

**왜 확장했나**
- Article은 publishedTime/tags/images가 있어야 Google "News/Article" 리치 결과 후보에 들어감
- canonical이 없으면 `/posts/foo?utm=...` 같은 변형 URL이 중복 색인됨
- 썸네일 이미지가 OG에 실리면 공유 시 매력도 향상

**변경 요점**
```ts
return {
  title: post.title,
  description,
  authors: [{ name: site.author.name, url: site.author.url }],
  keywords: post.tags ?? undefined,
  alternates: { canonical: canonicalPath },
  openGraph: {
    type: 'article',
    url: canonicalPath,
    title, description, siteName, locale,
    publishedTime: post.created_at,
    modifiedTime: post.updated_at,
    authors: [site.author.name],
    tags: post.tags,
    images: post.cover_image ? [{ url: post.cover_image }] : undefined,
  },
  twitter: { card: 'summary_large_image', title, description, images: [post.cover_image] },
}
```

**효과**
- Twitter/X 공유 시 `summary_large_image` 카드로 썸네일 + 제목 + 설명 렌더링
- Facebook/Slack/Discord 공유 시 article-specific OG로 발행일·저자·태그까지 전달
- canonical URL로 파라미터 변형 모두 동일 페이지로 통합 색인
- `keywords`는 modern Google엔 약한 신호지만 Naver에선 여전히 고려됨

### 2.6 JSON-LD: Article + BreadcrumbList (포스트 상세)

**왜 넣었나**
- **Article schema**: Google이 "블로그 글"로 명시적으로 인식 → 검색 결과에 저자/발행일/이미지 리치 스니펫 가능
- **BreadcrumbList schema**: 검색 결과에서 URL 대신 "Home › Develop › React › 제목" 형태 breadcrumb 표시 → CTR 향상
- 사이트에 이미 UI breadcrumb는 있지만 schema 없이는 검색 엔진이 구조를 파악 못함

**Article schema 구성**
```ts
{
  '@context': 'https://schema.org',
  '@type': 'Article',
  headline, description, datePublished, dateModified,
  author: { '@type': 'Person', name, url: GitHub URL },  // sameAs 효과
  publisher: { '@type': 'Person', name, url },
  mainEntityOfPage: { '@type': 'WebPage', '@id': postUrl },
  image: [cover_image],
  keywords: tags.join(', '),
}
```

**BreadcrumbList 구성**
- Home → 상위 카테고리들 → 현재 글 title 순서
- 각 position은 1부터 순차 증가
- item URL은 사이트 절대 경로

**효과**
- Article rich result 후보 등록 (Top Stories, Google News 등에도 잠재 후보)
- 저자 entity가 GitHub URL로 연결 → 추후 Google이 "같은 사람"으로 인식
- 검색 결과에 breadcrumb 경로 노출 → 사용자 신뢰도 향상

---

### 2.7 JSON-LD: WebSite + SearchAction (홈)

**왜 넣었나**
- `WebSite` schema는 사이트 레벨 entity를 Google에 명시
- `SearchAction`은 Google 검색 결과에 **Sitelinks Search Box**를 표시할 가능성을 열어줌 (브랜드 검색 시 "Search within blog" UI 노출)
- 한 번 설정해두면 별도 UI 변경 없이 검색 진입 경로 증가

**구성**
```ts
{
  '@type': 'WebSite',
  name, description, url,
  inLanguage: 'ko',
  publisher: { '@type': 'Person', name, url: GitHub },
  potentialAction: {
    '@type': 'SearchAction',
    target: { urlTemplate: `${site.url}/search?q={search_term_string}` },
    'query-input': 'required name=search_term_string',
  },
}
```

**효과**
- Google Knowledge Panel 후보 (브랜드 검색 시)
- 검색 결과 내 검색 박스 (Sitelinks Search Box) 후보
- `inLanguage: 'ko'` → 한국어 화자 타겟팅 신호

### 2.9 검색 페이지 noindex (`app/search`)

**왜 제외했나**
- Google Search Central 권장: **사이트 내 검색 결과 페이지는 robots로 색인 제외** (https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `q=...` 쿼리 변형이 모두 색인되면 중복 콘텐츠 페널티 + 크롤링 예산 낭비
- `follow: true`는 유지하여 해당 페이지에서 발견되는 글 링크는 계속 따라가게 함

**변경**
```ts
return {
  title: q ? `검색: ${q}` : '검색',
  robots: { index: false, follow: true },
}
```

### 2.10 사이트맵 고도화 (`app/sitemap.ts`)

**이전 문제**
- 모든 카테고리가 `lastModified: new Date()` → 매 요청마다 값이 바뀜 → 크롤러 신뢰도 하락
- `changeFrequency`, `priority` 없음 → 크롤러가 어느 URL을 자주 볼지 힌트 없음

**변경 요점**
```ts
const latestByCategory = new Map<string, string>()
for (const p of allPosts) {
  if (p.category_id && p.updated_at) {
    const prev = latestByCategory.get(p.category_id)
    if (!prev || p.updated_at > prev) latestByCategory.set(p.category_id, p.updated_at)
  }
}

// home: 가장 최신 글의 updated_at
// posts: 각 글의 updated_at, changeFrequency: 'monthly', priority: 0.8
// categories: 해당 카테고리 최신 글의 updated_at, 'weekly', 0.6
```

**효과**
- `lastModified`가 실제 콘텐츠 변경 시점과 일치 → 크롤러가 "정말 바뀌었네"라고 신뢰
- `priority` 계층: home(1.0) > posts(0.8) > categories(0.6) → 크롤링 우선순위 가이드
- `changeFrequency`: home 'daily', posts 'monthly', categories 'weekly' — 실제 운영 패턴에 맞는 빈도

### 2.11 RSS 피드 (`app/rss.xml/route.ts`)

**왜 만들었나**
- **재방문 유도**: 알고리즘 의존 없이 구독자 ↔ 작성자 직접 관계 형성
- **간접 SEO**: 피드 수집기가 RSS를 긁어가 외부에 노출 → 자연스러운 백링크 기회
- **크롤러 보조 신호**: Google은 RSS를 보조적 크롤링 힌트로 사용
- **독자 친화**: 개발자 독자층은 Feedly/Inoreader 습관이 남아있음

**구현 특징**
- Next.js Route Handler(`app/rss.xml/route.ts`)로 구현 → `/rss.xml` 경로에 XML 직접 반환
- 최근 20개 published 글만 포함 (피드 크기 절제)
- `lastBuildDate`를 최신 글 기준으로 설정 → 애그리게이터의 refresh 판단 근거
- XML 이스케이프 헬퍼로 `&`, `<`, `>`, `"`, `'` 치환 → XML 파싱 오류 방지
- `<![CDATA[...]]>`로 제목·설명 감쌈 → 마크다운/HTML이 섞여도 안전
- Cache-Control `s-maxage=600, stale-while-revalidate=86400` → 10분 ISR + 24시간 stale fallback

**Layout 연동**
```ts
alternates: {
  types: { 'application/rss+xml': [{ url: '/rss.xml', title: 'ShyLog RSS' }] },
}
```
→ `<head>`에 자동 `<link rel="alternate" type="application/rss+xml" ...>` 삽입
→ 브라우저와 피드 리더가 피드 존재 자동 탐지

**효과**
- Feedly/Inoreader 사용자가 사이트 URL만 입력해도 자동으로 피드 검출
- Google이 RSS를 보조 신호로 수집

## 4. 후속 작업

### 4.1 Naver Search Advisor 인증 (미완료)
1. https://searchadvisor.naver.com/ 접속 → 사이트 등록
2. HTML 태그 방식 선택 → 제공받은 코드 복사
3. Vercel Dashboard → Project → Settings → Environment Variables
4. `NEXT_PUBLIC_NAVER_VERIFICATION=<code>` 추가 후 재배포
5. Naver에서 검증 완료 후 sitemap.xml 제출

### 4.2 Google Analytics 도입 (선택)
- GA4 또는 Umami/Plausible 같은 privacy-friendly 대안
- 유입 키워드/체류시간 모니터링으로 콘텐츠 최적화

### 4.3 향후 고려사항
- **글별 커스텀 OG 이미지 파일 업로드**: 현재는 글 상세에 `opengraph-image.tsx`가 글 제목 기반 동적 이미지를 생성. 필요 시 업로드한 `cover_image`로 우선 표시하도록 수정 가능
- **관련 글 추천** (related posts): 같은 카테고리/태그 교집합 기반 → 내부 링크 밀도 증가 → SEO 긍정
- **AMP 또는 Speed Optimization**: LCP < 2.5s 유지 관리 필요
- **Schema.org FAQ/HowTo**: 해당 구조의 글이 있을 때 적용하면 리치 결과 확장
