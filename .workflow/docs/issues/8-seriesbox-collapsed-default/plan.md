# Plan — Issue #8: SeriesBox 기본값을 접힘(앞 5개 미리보기)으로 변경

- **Issue:** [#8](https://github.com/NJ97S/personal-blog/issues/8) — standalone (no milestone/epic, no sibling issues)
- **PM:** lead-issue run
- **Owns:** `components/SeriesBox.tsx`

## Goal
글 상세 페이지 상단의 같은-카테고리 글 목록(`SeriesBox`)이 지금은 기본 펼침 상태로 카테고리 공개글 전체를 노출해, 글이 많은 카테고리에서 이 섹션이 과도하게 길어진다. 기본값을 **접힘**으로 바꾸고, 접힌 상태에서는 목록 앞에서 **최대 5개**만 미리보기로 보여준다. "펼치기"로 전체를 열 수 있고, 카테고리 글이 5개 이하면 미리보기가 곧 전체이므로 토글 자체를 숨긴다. 이 변경은 `SeriesBox` 컴포넌트 내부의 상태·렌더링 로직에 한정된다.

## Scope Fence (confirmed in Phase 1)

**Must do**
- 기본 상태를 펼침 → 접힘으로 변경 (초기 진입 시 "펼치기" 버튼 노출).
- 접힘 상태: 전달받은 목록 순서(오래된→최신) 그대로 앞에서 최대 5개만 노출.
- 펼침 상태: 전체 목록 노출, 버튼 "숨기기".
- 카테고리 글이 5개 이하면 "펼치기/숨기기" 토글 버튼을 렌더링하지 않음(전체가 그대로 보임).
- 하단 `n/total` 위치 인디케이터는 모든 경우 유지.
- 현재 글이 노출 목록 안에 있으면 기존 활성(굵게) 하이라이트 유지.

**Must NOT touch**
- `app/posts/[slug]/page.tsx` — 카테고리 글 조회/정렬(created_at 오름차순) 및 prev/next 네비게이션. 데이터는 지금처럼 전량 전달받아 컴포넌트에서 slice.
- 그 외 컴포넌트/서버 액션/DB/스타일 시스템.

**Sequencing**
- 선행/후행 의존성 없음. 단독 착수·머지 가능.

## Approach

**채택: 컴포넌트 내부 클라이언트 slice + 기본 접힘.**
`SeriesBox`는 이미 부모(`app/posts/[slug]/page.tsx`)로부터 해당 카테고리의 공개글 **전체 배열**을 `posts` prop으로 전달받는 클라이언트 컴포넌트다. 따라서 서버 쿼리를 건드리지 않고 컴포넌트 내부에서 (1) 초기 접힘/펼침 상태의 기본값을 접힘으로 두고, (2) 접힘일 때 앞 N개만, 펼침일 때 전체를 렌더링하고, (3) 전체 개수가 미리보기 개수 이하일 때 토글을 숨기면 요구사항이 모두 충족된다.
- *why:* `app/posts/[slug]/page.tsx`가 카테고리 공개글을 정렬해 조회한 뒤 그 배열 전체를 `SeriesBox`에 넘기고 있어, 노출 개수 제한은 순수 클라이언트 렌더링 결정으로 처리 가능하다(서버 변경 불필요).
- *why:* `SeriesBox`는 이미 접힘/펼침 토글 상태와 그에 따른 목록 렌더링을 갖고 있으므로, 새 개념 도입 없이 기본값과 "무엇을 렌더링하는가"만 바꾸면 된다.

**기각한 대안**
- **서버에서 5개만 조회/전달:** 스코프 펜스가 명시적으로 금지(page.tsx 불가침, 클라이언트 slice로 결정). 또한 펼치기 시 전체가 필요하므로 서버에서 다시 전체를 받아와야 해 왕복만 늘어난다.
- **CSS max-height 접힘 애니메이션:** 요구사항에 없는 복잡도. "앞 5개 미리보기"는 개수 제한이지 높이 제한이 아니므로 부적합.

## Design decisions
1. **미리보기 개수 = 접힘 임계값 = 5.** 접힘 상태 노출 개수와 "토글을 숨기는 경계"를 동일한 5로 둔다. 전체가 5개 이하면 접힘=펼침이라 토글이 무의미하므로 숨긴다. — *why:* 이슈에서 확정된 값(앞 5개 / 5개 이하 토글 숨김).
2. **정렬·선택 기준은 "전달받은 순서의 앞에서".** 별도 재정렬 없이 부모가 준 순서(오래된→최신) 그대로 앞 5개. — *why:* page.tsx가 created_at 오름차순으로 정렬해 전달하며, 이슈 인터뷰에서 "목록 앞에서 5개"로 확정됨. 현재 글이 앞 5개 밖이면 접힘 미리보기에는 안 보일 수 있으나 이는 의도된 선택이며, `n/total` 인디케이터가 위치를 계속 알려준다.
3. **위치 인디케이터는 토글과 독립적으로 유지.** 토글 버튼을 숨기는 경우(≤5개)에도 하단 `n/total` 표시는 남긴다. — *why:* 현재 푸터 영역은 토글과 위치 표시를 함께 담고 있어, 토글만 조건부로 제거하고 위치 표시는 보존해야 한다(레이아웃은 Developer 재량).

## Constraints
- 클라이언트 컴포넌트(`'use client'`) 유지. 서버 데이터 흐름·prop 인터페이스 변경 없음(부모가 넘기는 값 그대로 사용).
- 기존 디자인 토큰/마크업 구조를 그대로 유지하고 상태·조건 렌더링만 변경.

## Edge cases
- **글 정확히 5개:** 토글 없음, 5개 전부 노출.
- **글 6개 이상:** 접힘 시 앞 5개 + "펼치기"; 펼치면 전체 + "숨기기"; 다시 접기 가능.
- **현재 글이 앞 5개 밖(예: 12개 중 10번째):** 접힘 미리보기엔 현재 글이 없어 굵게 하이라이트가 안 보일 수 있음(의도됨). `n/total`은 10/12로 정확히 표시.
- **글 1개:** 부모가 `posts.length > 0`일 때만 렌더링하므로 최소 1개. 토글 없이 그 1개만 노출.

## Non-goals
- 서버 조회/정렬 로직 변경, prev/next 네비게이션 변경 (Must NOT touch).
- 접힘/펼침 애니메이션, "N개 더 보기" 점진 로딩 등 부가 UX.
- 미리보기 개수를 사용자/관리자가 설정 가능하게 만드는 것(고정 5).
- 다른 카테고리 관련 컴포넌트(CategorySidebar/Tree 등) 변경.

## Acceptance
- 카테고리 공개글 6개 이상인 글: 진입 시 접힘, 앞 5개만, 버튼 "펼치기".
- "펼치기" → 전체 + "숨기기", 재클릭 → 다시 앞 5개.
- 카테고리 공개글 5개 이하인 글: 토글 버튼 없이 전체 노출.
- 현재 글이 노출 5개 안이면 활성 하이라이트 정상.
- `n/total` 위치 표시는 전 경우 유지.
- 실제 브라우저에서 접힘/펼침 전환·리플로우 확인(동적 UI 검증).
