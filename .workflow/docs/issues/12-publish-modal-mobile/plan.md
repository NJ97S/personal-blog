# Plan — Issue #12: 출간 모달 모바일 (세로 스크롤 + 배경 잠금)

> **For the next worker:** 이 문서는 세션 맥락이 없는 사람이 읽어도 이해되도록 자기완결적으로 씁니다. 개인 블로그(ShyLog, Next.js 14 App Router + Tailwind)의 관리자(admin) 영역을 폰에서 쓸 수 있게 만드는 에픽 **"관리자 모바일 최적화"**(GitHub milestone #1, 트래킹 이슈 #15, 설계: `.workflow/docs/epics/admin-mobile/design.md`)의 5개 자식 이슈 중 **C = 출간 모달**을 다룹니다. 이 계획은 *무엇을·왜*만 담습니다. *어떻게*(구조·시그니처·라인 단위 선택)는 Developer가 결정합니다.

## Goal

포스트 작성/수정 화면에서 "출간하기"를 누르면 뜨는 **출간 모달**(`components/PublishModal.tsx`)이 폰 세로 화면(~360–430px)에서 내용이 길어져도 **내부 스크롤로 모든 필드와 하단 출간/취소 버튼, 그리고 (있을 경우) 삭제 영역까지 도달**할 수 있게 만든다. 모달이 열려 있는 동안 **배경 본문 스크롤을 잠근다.** 아울러 모달 프레임이 소유한 컨트롤(닫기·취소·출간·커버 업로드/제거·공개설정 토글)이 폰에서 무리 없이 눌리는 크기인지 보정한다. 데스크톱 표시는 기존과 시각적으로 동일하게 유지한다.

## Scope Fence (Phase 1에서 확정)

### Must do
- 폰에서 모달 높이가 뷰포트를 넘으면 **내부 스크롤**로 상단 필드부터 dangerZone·하단 버튼까지 모두 도달 가능(`max-height` + `overflow-y`).
- 모달 **열림 중 배경(문서 body) 스크롤 잠금**, 닫힘/언마운트 시 원복.
- 모달 **자체 컨트롤**(닫기, 취소, 출간, 커버 파일 선택/교체, 제거, 전체공개/비공개 토글)이 폰에서 편히 눌리는 터치 타깃.
- 데스크톱(`md:`↑)은 시각적으로 동일, 포커스 트랩·Esc 동작 유지.
- `npm run lint` / `npm run build` 통과, **프로덕션 빌드**(`next build && next start`) 실브라우저 확인.

### Must NOT touch
- `app/admin/posts/new/NewPostForm.tsx`, `app/admin/posts/[id]/edit/EditPostForm.tsx` — 모달 호출부(형제 이슈 B #11 소유). 읽기만 가능.
- `dangerZone` / `categoryPicker`로 **넘어오는 내용 마크업 자체**(삭제 버튼, `CategoryPicker`가 렌더하는 카테고리 `<select>` 등) — 부모/형제 B 소유. C는 그 노드를 **담는 그릇(슬롯)만** 반응형으로 만들고 내용은 그대로 렌더한다.
- 모달의 **prop 인터페이스(이름·시그니처) 유지** — 호출부를 바꾸지 않으므로 props를 추가/삭제/개명하지 않는다.
- 커버 이미지 업로드 로직(Supabase storage)·서버 액션·폼 제출 동작 — 변경 없이 **레이아웃/스타일만**.

### Sequencing
- 하드 의존 없음. 형제 이슈들과 소유 파일(`components/PublishModal.tsx` 단독)이 겹치지 않아 독립 진행. #11(B)이 별도 worktree에서 진행 중이나 소유 파일이 달라 충돌하지 않는다.

## Approach

**채택: 인라인 모달 프레임을 "뷰포트에 갇힌 스크롤 컨테이너"로 전환 + 배경 스크롤 잠금 + 모바일 터치 타깃 보정 (모두 반응형 프리픽스로 데스크톱 무영향).**

핵심 3요소:
1. 모달 프레임에 뷰포트 기준 높이 상한을 두고, 내부에 세로 스크롤 영역을 만들어 하단 버튼까지 도달하게 한다.
2. 모달이 열린 동안 문서 body 스크롤을 잠그고, 닫히거나 컴포넌트가 사라질 때 반드시 원복한다.
3. 모달이 소유한 소형 컨트롤들의 폰 터치 타깃을 키운다(데스크톱은 반응형 프리픽스로 현행 유지).

### 검토 후 기각한 대안
- **모바일 전용 풀스크린 바텀시트/시트 UX 신설** — 기각. (a) 에픽 비목표가 "모바일 전용 신규 UX 신설 금지"(`design.md` Epic-level Non-goals). (b) 디자인 유지 + 반응형 보정이라는 에픽 방침에 어긋남. 기존 중앙 모달을 스크롤 가능하게만 만드는 것으로 Acceptance를 모두 충족한다.
- **모달을 `createPortal`로 body에 이동**(공개 측 `CategoryDrawer` 방식 모방) — 기각. *why:* 모달은 현재 호출부의 `<form>` 내부에 인라인 렌더되고 출간 버튼이 `type="submit"`으로 그 폼에 의존한다(근거는 아래 Design decisions). body로 포털하면 제출 버튼이 폼 밖으로 나가 **출간/저장이 깨진다.** 배경 잠금은 포털 없이도 body 스타일 토글만으로 달성 가능하므로 포털은 불필요하고 위험하다.
- **다이얼로그 전체를 한 덩어리로 스크롤**(헤더/푸터도 함께 스크롤) — 부분 채택 여지. Acceptance("내부 스크롤로 하단 버튼까지 도달")는 만족하지만, 스크롤 중 출간/취소 버튼이 시야에서 사라진다. 헤더/푸터를 고정하고 가운데 본문만 스크롤하는 편이 UX상 우수하다. **어느 쪽 구조로 갈지는 Developer 판단**에 맡기되(둘 다 Acceptance 충족), 본문이 길 때 하단 버튼 접근성이 신뢰성 있게 보장되는 쪽을 권장한다. **주의:** `dangerZone` 슬롯은 본문 그리드 뒤·푸터 앞에 놓인다(EditPostForm에서만 전달). "가운데 본문만 스크롤" 구조를 택하면 `dangerZone`이 스크롤 영역 밖에 남지 않도록 그 슬롯도 반드시 스크롤 컨테이너 안에 포함시켜야 한다(Acceptance: dangerZone까지 도달 가능).

## Design decisions (근거 명시)

- **모달은 포털 없이 현 위치(폼 내부)에 유지한다.**
  *why:* `components/PublishModal.tsx`는 `createPortal`을 쓰지 않고 호출부(`NewPostForm.tsx`, `EditPostForm.tsx`)의 `<form>` 안에 인라인 렌더된다. 모달 안의 출간 버튼이 `type="submit"`이라 폼 컨텍스트에 의존한다. 따라서 DOM 위치를 바꾸는 접근(포털)은 배제하고, `fixed` 포지셔닝으로 시각적 오버레이만 유지한다.

- **높이 상한 + 내부 스크롤은 반응형으로 넣되 데스크톱 표시를 바꾸지 않는다.**
  *why:* 현재 다이얼로그는 `max-height`/`overflow-y`가 전혀 없어 폰에서 하단 버튼이 화면 밖으로 나간다. 뷰포트 기준 높이 상한과 스크롤을 도입하면, 내용이 상한보다 짧은 데스크톱에서는 스크롤바가 나타나지 않아 시각적으로 동일하게 유지된다(안전한 무영향 개선).

- **배경 스크롤 잠금은 공개 측 기존 패턴을 재사용한다.**
  *why:* `components/CategoryDrawer.tsx`가 이미 `open` 동안 `document.body.style.overflow='hidden'`을 걸고 cleanup에서 원복하는 검증된 패턴을 쓴다. 새 메커니즘을 발명하지 않고 이 패턴을 따르면 코드베이스 일관성이 유지된다. PublishModal에는 이미 `open`에 묶인 Esc 처리 effect가 있어 같은 수명주기에 자연스럽게 얹을 수 있다.

- **터치 타깃 보정은 모달이 소유한 컨트롤에 한정하고 반응형으로 적용한다.**
  *why:* 닫기 버튼(28px), "제거" 텍스트 버튼, 커버 업로드 라벨, 취소/출간 버튼, 공개설정 토글은 모두 모달 프레임 소유(스코프 안). 이들만 폰에서 키우고 데스크톱은 반응형 프리픽스로 현행 유지한다. `dangerZone`/`categoryPicker`로 들어오는 내용(삭제 버튼 등)은 형제 B/부모 소유이므로 **건드리지 않는다.**

- **포커스 트랩/Esc는 그대로 동작해야 한다.**
  *why:* 포커스 트랩(`lib/use-focus-trap.ts`)은 다이얼로그 컨테이너 내부의 포커스 가능 요소를 매번 쿼리하므로, 내부에 스크롤 래퍼를 추가해도 컨테이너 하위에 있는 한 계속 유효하다. 구조 변경 시 포커스 트랩 대상 컨테이너(현재 `ref`가 걸린 요소)와 Esc 리스너의 수명주기를 깨지 않도록 유지한다.

## Constraints
- prop 인터페이스 불변(호출부 미변경). 커버 업로드/서버 액션/제출 동작 불변. 순수 레이아웃·스타일 작업.
- `dangerZone`은 **선택적**이다: EditPostForm은 넘기고 NewPostForm은 넘기지 않는다. 두 경우 모두 스크롤·잠금이 올바로 동작해야 한다.
- 검증은 프로덕션 빌드로 한다 — `next dev`의 Fast Refresh는 앱 CSP(`unsafe-eval` 미허용)에 막혀 하이드레이션이 실패하므로 UI 검증에 쓰지 않는다(에픽 공통 규약).
- 크래프트 종이 디자인 톤(색·보더·타이포) 유지.

## Edge cases
- **아주 작은 폰 높이**: 커버 미리보기(aspect-video)까지 있어 내용이 뷰포트보다 훨씬 길 때에도 내부 스크롤로 최하단 출간/취소 버튼에 도달 가능해야 한다.
- **dangerZone 유무 차이**: 있을 때(수정 화면)와 없을 때(새 글) 모두 레이아웃/스크롤/잠금이 정상이어야 한다.
- **배경 잠금 원복**: 모달을 닫거나, 모달이 열린 채 페이지를 벗어나(언마운트) 도 body 스크롤이 반드시 원복돼야 한다(잠금이 남으면 페이지 전체가 얼어붙음).
- **데스크톱 회귀 없음**: 데스크톱에서 스크롤바 출현·중앙 정렬·너비 등 시각 변화가 없어야 한다.
- **iOS Safari의 body overflow 한계**: `overflow:hidden`이 iOS에서 배경 스크롤을 완벽히 막지 못할 수 있으나, 이는 코드베이스가 이미 채택한 CategoryDrawer 패턴과 동일한 수준이다. 새 UX 발명은 비목표이므로 기존 패턴과 동일한 동작을 목표로 하고, 그 이상(예: position:fixed body 기법)은 도입하지 않는다.
- **포커스/Esc 회귀 없음**: 열림 시 첫 요소 포커스, Tab 순환, Esc 닫기가 그대로 동작.

## Non-goals
- 모바일 전용 신규 UX(바텀시트, 풀스크린 시트) 신설 — 에픽 비목표.
- 모달을 포털로 이동 — 폼 제출 깨짐(위 근거).
- `dangerZone`/`categoryPicker` **내용** 마크업·터치 크기 변경 — 형제 이슈 B #11 및 부모 소유. (B의 Owns에 "EditPostForm이 모달에 넘기는 dangerZone 내용 자체의 마크업·터치 크기"가 명시됨.)
- 커버 업로드 로직/서버 액션/제출 동작 변경.
- 데스크톱 레이아웃의 의도적 시각 변경.
- viewport 메타 추가(이미 정상 주입 — 에픽 비목표).
