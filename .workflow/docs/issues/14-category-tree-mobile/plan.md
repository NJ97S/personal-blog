# Plan — #14 카테고리 관리 트리 모바일

> **For the next worker (zero context 가정):** 이 문서는 개인 블로그(ShyLog, Next.js 14 App Router + Tailwind, 크래프트 종이 디자인)의 **관리자 카테고리 관리 트리를 폰에서 쓸 수 있게 만드는** 작업 계획입니다. 에픽 "관리자 모바일 최적화"(GitHub milestone #1, 트래킹 이슈 #15)의 다섯 이슈 중 **Issue E**에 해당하며, 에픽 설계는 `.workflow/docs/epics/admin-mobile/design.md`에 있습니다. 이 계획은 *무엇을/왜*만 다루고, *어떻게*(줄 번호·클래스명·코드)는 Developer가 결정합니다. 형제 이슈 #10·#11·#12·#13은 이미 병합(CLOSED)되었습니다.

## Goal

관리자 카테고리 관리 화면(`/admin/categories`, 파일 `app/admin/categories/CategoryAdmin.tsx`)의 트리 행을 폰(~360–430px, 하한 320px 고려)에서 무리 없이 조작할 수 있게 반응형으로 보정한다. 구체적으로 (1) 각 행의 순서변경(위/아래)·편집·삭제 아이콘 버튼이 현재 28px로 손가락 터치에 작으므로 누르는 히트 영역을 키우고, (2) 좁은 화면에서 이름 + 4개 버튼이 한 줄에 몰려 잘리거나 겹치지 않게 레이아웃을 보정한다. 순서변경/편집/삭제/추가 기능과 데스크톱 표시는 그대로 유지한다.

## Scope Fence (Phase 1에서 사용자 승인 완료)

**Must do**
- 트리 각 행의 아이콘 버튼(위로/아래로/편집/삭제) 히트 영역을 폰에서 손가락으로 누를 만하게(권장 44px 지향) 확대. **아이콘 자체 크기는 유지**하고 누르는 영역만 키운다(형제 #11의 태그 삭제 버튼과 동일 방침).
- 좁은 화면에서 이름 + 버튼 클러스터가 잘리거나 겹치지 않게 레이아웃 보정(행 래핑 또는 폰에서 들여쓰기 축소 등).
- 순서변경(up/down)·편집·삭제·추가 기능은 기존 동작 그대로.

**Must NOT touch**
- `app/admin/categories/page.tsx`(공개 `Layout` 사용부, 서버 컴포넌트 진입점).
- 카테고리 서버 액션(`app/actions/categories.ts`) — 순수 프론트 레이아웃/스타일만, 동작 변경 없음.
- 편집 폼 그리드(`CategoryForm`, `CategoryAdmin.tsx:332`)는 이미 `md:` 스택이라 손대지 않는다.
- **드래그 앤 드롭 재정렬 도입 금지**(에픽 비목표) — 기존 up/down 버튼 방식 유지.
- 데스크톱(`md:` 이상) 표시는 시각적으로 실질 동일하게 유지.
- 트리 **렌더 depth 상한(3단계)** 변경 금지 — 아래 "Constraints" 참고.

**Sequencing**
- Depends on: 없음. 소유 파일 `app/admin/categories/CategoryAdmin.tsx` 단독이라 형제 이슈와 독립·병렬 진행 가능. 형제 #10·#11·#12·#13은 모두 CLOSED.

## Approach

### 채택: `CategoryAdmin.tsx` 트리 행 마크업에 Tailwind 반응형 프리픽스 + 버튼 히트 영역 확대만 추가
데스크톱 레이아웃은 손대지 않고, 폰 폭(`md:` 미만)에서만 (a) 아이콘 버튼의 히트 영역을 키우고 (b) 이름 행과 버튼 클러스터가 한 줄에서 넘칠 때 겹치지 않게 흐르도록(래핑 또는 들여쓰기 축소) 보정한다. 새 컴포넌트·상태·드래그 UX 없이 기존 `TreeRow`/`IconButton`의 className과 컨테이너 flex 계약 조정으로 끝낸다.

*why:* 이 화면은 `app/admin/categories/page.tsx`가 공개 `Layout`(`mx-auto ... max-w-* px-4`) 안에서 단일 컬럼으로 흐르므로 바깥 셸은 이미 반응형이다. 깨지는 지점은 트리 행 내부 두 곳뿐 — ① `IconButton`이 `h-7 w-7`(28px, `CategoryAdmin.tsx:299`)로 4개(`:253-281`)가 `gap-1` 한 줄(`:252`)에 몰려 터치 타깃이 작고, ② 행이 `flex items-center gap-2`(`:219`)에 wrap이 없어 이름(`flex-1 min-w-0`, `:239`) + 버튼 클러스터가 좁은 폭에서 빠듯하다. 에픽 설계(`design.md`의 "Approach / architecture")가 정한 방침 — 공용 셸을 새로 만들지 않고 화면별로 Tailwind 반응형 프리픽스와 최소 조건부만 더한다 — 과 정확히 일치한다.

### 기각한 대안
- **드래그 앤 드롭 재정렬 도입**: 에픽 비목표로 명시적 제외(`design.md`의 "Epic-level Non-goals", 이슈 본문 "드래그 재정렬 도입 금지"). up/down 버튼 방식을 유지한다.
- **버튼을 "더보기" 오버플로 메뉴(⋯)로 접기**: 새 클라이언트 상태·팝오버 UX 도입이라 "디자인 유지 + 반응형 보정" 방침을 넘어선다. 4개 버튼은 래핑/full-width 배치로 충분히 수용 가능하므로 과함.
- **행을 항상 세로 스택으로 재설계**: 데스크톱 표시까지 바꿔 회귀 위험. 반응형 프리픽스로 폰에서만 조정하는 편이 최소·정확하다.
- **트리 렌더 depth를 늘려 임의 깊이 지원**: 스코프 밖(레이아웃 보정이 목적이며 depth 상한은 기존 동작). 아래 Constraints 참고.

## Design decisions (각 항목 코드 근거 명시)

1. **아이콘 버튼의 히트 영역을 폰에서 확대하되(권장 44px 지향) 아이콘 자체 크기(`h-4 w-4`)는 유지한다.**
   - *why:* `IconButton`이 `flex h-7 w-7 ...`(28px, `CategoryAdmin.tsx:299`)로 위로/아래로/편집/삭제 4개(`:253-281`)를 렌더하는데, 28px는 모바일 권장 터치 타깃 44px에 못 미친다. 형제 이슈 #11이 태그 삭제 버튼(16px)에 대해 "아이콘 크기는 유지, 누르는 영역만 확대"로 처리한 선례를 따른다(에픽 설계 및 #11 plan). 아이콘 시각 크기를 유지하면 데스크톱 표시가 흔들리지 않는다.

2. **버튼 히트 영역 확대가 한 줄 폭을 더 잡아먹으므로, 폰에서는 이름 행과 버튼 클러스터가 겹치지 않게 흐르도록(행 래핑 또는 클러스터를 이름 아래로 내림) 보정한다. 데스크톱은 현행 한 줄 배치 유지.**
   - *why:* 행이 `flex items-center gap-2 px-3 py-2`(`:219`)에 `flex-wrap`이 없고, 이름은 `flex-1 min-w-0`(`:239`), 버튼 클러스터는 `flex items-center gap-1`(`:252`) 한 줄이다. 버튼을 키우면(결정 1) 4개 클러스터의 폭이 늘어 좁은 폰에서 이름과 충돌한다. 폰에서 버튼 클러스터가 이름 아래 줄로 흐르거나 행이 래핑되게 하면, 확대된 타깃이 들어갈 자리가 생기고 이름은 온전히 보인다. 데스크톱은 기존 한 줄 space-between 느낌을 유지한다.

3. **들여쓰기는 폰에서 과하지 않게 유지/축소하되, 실제 최대 들여쓰기는 52px(depth 2)임을 전제로 최소 보정만 한다.**
   - *why:* 들여쓰기는 `style={{ paddingLeft: 12 + depth * 20 }}`(`:220`). 렌더 재귀는 최상위(depth 0) → 자식(depth 1) → 손자(depth 2)까지만 행으로 그리고, 손자의 `renderChild={() => null}`(`:176`)이 그 아래를 자른다. 따라서 **실제 렌더되는 최대 들여쓰기는 `12 + 2*20 = 52px`**이며, 이슈 배경의 "depth 3 → 72px"는 공식값일 뿐 렌더되지 않는다. 52px는 치명적이지 않으므로, 결정 2의 래핑이 클리핑을 이미 해소한다면 들여쓰기 축소는 선택 사항이다. 다만 폰에서 여유가 부족하면 폰 한정으로 per-depth 들여쓰기를 줄이는 것도 허용한다(데스크톱 값은 유지).

4. **편집 모드 행(`CategoryForm`)과 "새 카테고리" 추가 폼은 손대지 않는다.**
   - *why:* 편집 시 행은 `editing`이면 `CategoryForm`을 `flex-1`로 렌더(`:222-236`)하고, `CategoryForm`은 이미 `grid grid-cols-1 gap-2 md:grid-cols-[...]`(`:332`)로 폰에서 세로 스택된다. 추가 폼도 같은 컴포넌트다. 이미 반응형이므로 이 이슈의 대상이 아니다(스코프 펜스 "Must NOT touch").

5. **모두 기존 크래프트 디자인 토큰과 유틸리티로 처리, 서버 액션·prop 시그니처·삭제 확인 로직 변경 없음.**
   - *why:* 삭제는 `onDelete`에서 브라우저 `confirm()`(`:88`)으로 확인하고 `deleteCategory` 서버 액션을 호출한다. 목표는 순수 레이아웃/스타일이므로 확인 UX·서버 액션·`TreeRow`/`IconButton`의 prop 시그니처는 그대로 두고 className/컨테이너 flex만 조정한다. 크래프트 토큰(`craft-*`, `ink-*`)을 재사용해 새 색/보더를 도입하지 않는다.

## Constraints
- 데스크톱(`md:` 이상) 표시는 시각적으로 실질 동일해야 한다. 반응형 프리픽스는 폰(`md:` 미만) 조정에만 쓴다.
- 크래프트 디자인 토큰(`craft-card`, `craft-*`, `ink-*`) 유지 — 새 색/보더 없이 기존 유틸리티 재사용.
- 트리 **렌더 depth 상한은 3단계(depth 0·1·2)로 기존과 동일하게 유지**한다. 데이터 모델(`lib/category-tree.ts`의 `buildTree`)은 임의 깊이 트리를 만들 수 있으나 `CategoryAdmin.tsx`가 손자 아래를 렌더하지 않는 것은 기존 동작이며, 이 이슈에서 바꾸지 않는다.
- 서버 액션·`prop` 시그니처·삭제 확인(`confirm`) 로직 변경 없음.
- `npm run lint`와 `npm run build` 통과. UI 검증은 프로덕션 빌드(`next build && next start`)로 실브라우저 확인 — `next dev`는 Fast Refresh가 앱 CSP(`unsafe-eval` 미허용)에 막혀 하이드레이션이 실패하므로 UI 검증에 쓰지 않는다(에픽 design.md 및 프로젝트 메모리 근거).

## Edge cases
- **긴 카테고리 이름 + slug + "(N개 글)" 배지 동시**: 이름 문단은 `flex-1 min-w-0`(`:239`) 안에 있으므로 폰에서 줄바꿈/축소되어야 하고, 버튼 클러스터가 이름에 밀려 잘리거나 겹치지 않아야 한다.
- **depth 2(최대 들여쓰기 52px) 행 + 확대된 버튼**: 가장 빠듯한 조합. 이 경우에도 이름과 4버튼이 겹치지 않고 조작 가능해야 한다.
- **편집 모드로 전환된 행**: `CategoryForm`(이미 반응형)이 뜨며, 버튼 클러스터 대신 폼이 `flex-1`로 자리한다. 보정이 이 상태를 깨지 않아야 한다.
- **비활성(`disabled`) 버튼**: `pending` 중 버튼은 `disabled:opacity-40`(`:299`)로 흐려진다. 히트 영역 확대가 이 비활성 표시를 바꾸지 않아야 한다.
- **320px 하한**: 버튼 클러스터가 폰에서 한 줄에 안 들어가면 래핑/스택으로 흘러 겹치지 않아야 한다.
- **데스크톱 회귀 없음**: `md:` 이상에서 행·버튼 모양이 현행과 사실상 동일해야 한다.

## Non-goals
- 형제 이슈가 소유하는 다른 admin 화면(#10·#11 에디터, #12 출간 모달, #13 글 목록 — 모두 CLOSED) 변경.
- 드래그 앤 드롭 재정렬 등 모바일 전용 신규 UX(에픽 비목표).
- 트리 렌더 depth 상한 확대 또는 임의 깊이 지원.
- 카테고리 서버 액션(`app/actions/categories.ts`)·삭제 확인 UX·조회 로직 변경.
- `app/admin/categories/page.tsx`(진입점)·공개 `Layout` 변경.
- 편집/추가 폼(`CategoryForm`) 레이아웃 변경(이미 반응형).

## Acceptance (이슈 #14 기준)
- 폰에서 트리 각 행의 조작 버튼이 손가락으로 누를 만한 크기다.
- 깊은 depth에서도 이름/버튼이 잘리거나 겹치지 않는다(래핑 또는 들여쓰기 축소).
- 순서변경/편집/삭제/추가 기능은 기존대로 동작한다.
- 데스크톱 표시는 실질적으로 동일하다.
- `npm run lint`/`build` 통과, 프로덕션 빌드 실브라우저 확인.
