# Plan — Issue #11: 에디터 셸·하단 액션바·입력 모바일

- **Issue:** [#11](https://github.com/NJ97S/personal-blog/issues/11) · **Epic(milestone):** 관리자 모바일 최적화 (#15 트래킹)
- **형제:** #10(에디터, 머지됨) · #12(출간모달) · #13(글목록) · #14(카테고리트리)
- **Owns:** `components/PostEditorShell.tsx`, `app/admin/posts/new/NewPostForm.tsx`, `app/admin/posts/[id]/edit/EditPostForm.tsx`, `components/TitleInput.tsx`, `components/TagInput.tsx` (+ `EditPostForm`이 모달에 넘기는 dangerZone 삭제 버튼 마크업)

## Goal
관리자 글쓰기 화면(신규/편집)의 **에디터 페이지 크롬**을 폰(~360–430px)에서 쓸 수 있게 보정한다. 구체적으로 ① 하단 고정 액션바가 폰에서 가로로 넘치지 않게 하고 iOS 홈 인디케이터 안전영역을 반영, ② 데스크톱 기준 매직넘버로 잡힌 에디터 높이가 폰에서 액션바와 겹치지 않게 정합, ③ 최상단 제목 입력이 폰에서 과하게 크지 않고 길면 다음 줄로 넘어가 전체가 보이게, ④ 태그 삭제 등 작은 터치 타깃을 손가락으로 누를 만하게 키운다. 기존 크래프트 디자인과 데스크톱 레이아웃은 그대로 유지하고, 에디터 위젯 자체(#10)·출간 모달 내부(#12)·서버 액션은 건드리지 않는다.

## Scope Fence (Phase 1 확정)
**Must do**
- 하단 액션바: 폰에서 넘치지 않게(래핑/재배치), `env(safe-area-inset-bottom)` 반영, 바 높이에 맞춰 본문 하단 예약 공간 정합.
- 에디터 높이: 폰에서 상단 요소(제목·태그·#10이 추가한 모바일 미리보기 토글) 높이에 관계없이 액션바와 겹치지 않게 반응형으로.
- 제목: 폰에서 글씨 축소 + 길면 줄바꿈(전체 노출). `name="title"` 제출·slug 자동생성(`onBlur`, 신규 폼)·`required` 유지.
- 태그 삭제 터치 타깃 확대(+ dangerZone "이 글 삭제" 버튼 터치 크기).
- 데스크톱 레이아웃 시각적 동일.

**Must NOT touch**
- `MarkdownEditor.tsx`/`useMarkdownScrollSync.ts`(→ #10). 단 폼이 넘기는 **height 값**은 조정 가능(prop 인터페이스는 유지).
- `PublishModal.tsx` 내부 레이아웃(→ #12). 폼은 모달을 열고 prop만 전달하며 prop 인터페이스 유지.
- `app/admin/posts/page.tsx`(#13), `CategoryAdmin.tsx`(#14).
- 서버 액션(`app/actions/posts.ts`) 및 폼의 데이터 계약(제출 필드명, dirty 추적, Cmd/Ctrl+S 임시저장, `useHydrated`, 토스트).

**Sequencing**: #10 머지 완료(main 반영). 하드 의존 없음. 단독 진행 가능.

## Approach

**채택: 에디터 페이지 크롬을 구성하는 자기 소유 컴포넌트(셸·두 폼·제목·태그)에 Tailwind 반응형 + 최소한의 클라이언트 로직을 더해 폰 대응.**
문제 지점이 모두 #11이 소유한 파일 안에 있어, 인접 이슈(에디터 위젯/모달/서버)를 건드리지 않고 해결 가능하다.
- **하단 액션바**: 셸의 고정 바와 폼이 넘기는 액션 내용(나가기 / 에러메시지·임시저장·출간하기)을 폰에서 넘치지 않게 재배치하고 안전영역을 반영. 인라인 에러메시지가 버튼과 한 줄에 있어 넘침의 주원인이므로 폰에서의 배치를 조정한다(정확한 방식은 Developer 재량).
- **에디터 높이**: 폰에서 액션바와 겹치지 않도록, 폼(및 필요 시 셸)에서 반응형 높이를 준다. 폼은 이미 클라이언트 컴포넌트이므로 모바일에 맞는 높이 값을 넘기거나 셸을 높이-채움 구조로 바꾸는 선택이 가능하다. 어느 쪽이든 **MarkdownEditor의 `height` prop 인터페이스는 유지**하고 #10 파일은 건드리지 않는다.
- **제목**: `<input>`은 한 줄이라 줄바꿈이 원천 불가하므로 **auto-grow `<textarea>`로 전환**해 긴 제목이 시각적으로 여러 줄로 감기게 하고, 폰에서 글씨 크기를 낮춘다(데스크톱은 기존 크기 유지). 제목은 **하드 줄바꿈 없이 한 값**으로 유지(Enter로 실제 개행이 들어가지 않도록) — 감김은 시각적 소프트랩만.
- **태그/삭제 버튼**: 제거 버튼의 터치 히트 영역을 키운다(아이콘 시각 크기는 유지 가능).

**기각한 대안**
- **제목을 `<input>` 유지 + truncate만:** 사용자가 "잘리지 말고 줄 넘어가서 전체가 보이게"를 명시 → truncate는 요구 미충족.
- **에디터 높이를 #10의 globals.css/MarkdownEditor에서 처리:** 펜스 위반(#10 소유). 폼/셸(#11 소유)에서 해결 가능하므로 불필요.
- **액션바 에러를 무조건 토스트로만 이전:** 데스크톱 동작 변경 위험 + 폼 계약(에러 표시) 영향. 폰 레이아웃만 조정하는 편이 안전.

## Design decisions
1. **제목은 `<input>` → auto-grow `<textarea>` 전환.** — *why:* `TitleInput`이 `<input type="text">`라 줄바꿈이 불가능하고 `text-4xl`이 폰에서 과대. 사용자가 "길면 줄 넘어가 전체 노출"을 요구. `<textarea>`도 `name`으로 폼 제출되며 소프트랩으로 감긴다. 제목 값에 하드 개행이 들어가지 않도록 Enter는 억제(HOW는 Developer). slug 자동생성 `onBlur`(신규 폼)·`required`·placeholder·밑줄 스타일은 유지.
2. **폰 글씨 크기만 낮추고 데스크톱은 유지.** — *why:* `text-4xl`(36px)이 좁은 화면에서 과함. 반응형 프리픽스로 폰만 축소, `md:`↑는 기존 크기 → 데스크톱 시각 불변.
3. **에디터 높이는 #11 소유 파일(폼/셸)에서 반응형으로.** — *why:* `calc(100vh - 260px)`의 260px는 데스크톱 상단 여백 기준 매직넘버인데, 폰에선 제목(축소/감김)·태그·#10이 추가한 미리보기 토글로 상단 높이가 달라 액션바와 겹칠 수 있다. 폼이 값을 넘기고 셸이 바를 소유하므로 #10을 건드리지 않고 해결 가능.
4. **하단 액션바는 폰에서 재배치 + 안전영역.** — *why:* 셸의 고정 바가 한 줄 `justify-between`이고, 폼의 우측 클러스터에 인라인 에러메시지까지 있어 폰에서 넘친다. iOS 홈 인디케이터를 위해 `env(safe-area-inset-bottom)`가 필요하고, 바가 (예: 래핑으로) 높아지면 본문의 하단 예약 공간도 맞춰야 콘텐츠와 겹치지 않는다.
5. **태그 제거/삭제 버튼 히트 영역 확대.** — *why:* 태그 제거 버튼이 16px로 44px 권장 미만. 아이콘 크기는 유지하되 누르는 영역을 키운다. IME-safe 입력 로직·`name` 제출·최대 10개·중복 방지는 유지.
6. **인접 계약 불변.** — *why:* 폼은 MarkdownEditor(`height` prop)·PublishModal(prop 세트)을 소비한다. 이 인터페이스를 바꾸면 #10/#12와 충돌. 넘기는 height 값만 조정하고 모달 prop은 그대로 전달한다.

## Constraints
- 모두 클라이언트 컴포넌트. 폼 데이터 계약 유지: 제출 필드(`title`/`tags`/`content` 등), dirty 추적, Cmd/Ctrl+S 임시저장, `useHydrated` 게이팅, sessionStorage 토스트, `onChange` 더티.
- `MarkdownEditor`·`PublishModal`의 prop 인터페이스 불변(값만 조정).
- `PublishModal`은 폼의 **외부 `<form>` 안에** 렌더링되어 그 안의 submit 버튼이 폼을 제출한다(출간 흐름). 폼/셸을 손볼 때 이 form 포함 구조와 submit 계약을 깨지 않는다.
- 크래프트 디자인 토큰·데스크톱 레이아웃 보존.

## Edge cases
- **아주 긴 제목**: 여러 줄로 감겨도 액션바/에디터 높이와 겹치지 않아야.
- **제목에 개행 붙여넣기/Enter**: 하드 개행이 값에 들어가지 않고 한 줄 제목으로 유지.
- **폰에서 에러메시지 표시 중** 액션바가 깨지지 않아야.
- **회전/리사이즈로 브레이크포인트 교차** 시 작성 내용 유지.
- **다크모드**·slug 자동생성·임시저장 단축키 회귀 없음.
- **태그 여러 개로 줄바꿈된 상태**에서 제거 버튼이 눌리는 크기.

## Non-goals
- 에디터 위젯 내부/에디터 전역 CSS → #10(머지됨).
- 출간 모달 내부 레이아웃·세로 스크롤·배경 잠금 → #12.
- 글 목록(#13), 카테고리 트리(#14).
- 서버 액션·데이터 흐름 변경.
- 데스크톱 시각 변경.

## Acceptance
- 폰에서 하단 액션바의 나가기/임시저장/출간하기(+에러메시지)가 겹치거나 잘리지 않고, iOS 홈 인디케이터 영역을 침범하지 않는다.
- 에디터 높이가 폰에서 상단 요소 높이에 관계없이 액션바와 겹치지 않는다.
- 제목이 폰에서 과하지 않은 크기이고, 길면 다음 줄로 감겨 전체가 보인다(잘리지 않음). 제출 제목에 하드 개행이 없다.
- 태그 삭제·글 삭제 버튼이 손가락으로 누를 만하다.
- 데스크톱 레이아웃은 시각적으로 동일. slug 자동생성·임시저장·다크모드 회귀 없음.
- `npm run lint`/`build` 통과, 프로덕션 빌드(`next build && next start`) 실브라우저 확인(개발 모드는 CSP로 하이드레이션 실패하므로 미사용).
